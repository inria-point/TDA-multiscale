# qPHD на разных масштабах — расширение статьи

Расширение работы по multi-scale intrinsic dimension ([оригинальный код](https://github.com/candelabrum/PHDQ/blob/main/scripts/phd_scale.py)).
Цель — понять, **какие изменения в текстах влияют на размерность на разных масштабах**.

Датасет — FLAT (`../data_completion/`): 4 жанра × 5 источников (human + 4 генератора),
по 500 текстов в каждом файле. Эмбеддер — **ModernBERT-base**, локально на GPU макбука (MPS).

---

повторные прогоны идут в разы быстрее. Кэш в гит не коммитится.

## Что такое qPHD — в двух словах

Берём текст, прогоняем через ModernBERT, получаем **облако точек**: по одной точке
на токен (768 измерений). У этого облака есть внутренняя размерность — её и меряем.

Оценка строится на том, как растёт суммарная длина минимального остовного дерева (MST)
при увеличении числа точек: `S(n) ~ n^(1 − 1/d)`. Логарифмируем, фитим прямую,
из наклона достаём `d`.

**Идея q**: если перед суммированием выбросить часть рёбер MST, мы посмотрим на облако
в другом масштабе. Короткие рёбра — это локальная структура (соседние по смыслу токены,
служебные слова, пунктуация), длинные — глобальная (редкие термины, имена, числа).

Три режима обрезки:

| обозначение | что делаем | какой масштаб видим |
|---|---|---|
| `q_small` | выбрасываем долю q **коротких** рёбер | крупный |
| `q_large` | выбрасываем долю q **длинных** рёбер | мелкий |
| `q0.5_range` | обрезаем с обеих сторон, оставляем центральные 0.5 | средний, скользящее окно |

### Как считается одно измерение

```
1. фиксируем L                       → L = 256 токенов
2. строим сетку n из L               → 8 значений: 51, 64, 81, 102, 128, 161, 203, 256
3. для каждого n:
      32 раза:  взять n точек из пула  →  MST  →  m = n−1 рёбер, отсортировать
                                        →  выбросить долю q  →  сумма оставшихся = S
      усреднить S по 32 повторам
4. фит log S по log n на 8 точках     → наклон b → d = 1/(1−b)
```

MST строится один раз на подвыборку и переиспользуется для всех q и всех режимов —
обрезка это просто разная сумма по одному отсортированному списку рёбер.

Итог: **d при данном q считается по обрубкам MST из (1−q)·(n−1) рёбер**. Число рёбер
в сумме не постоянно внутри одного измерения — и не может быть, весь метод в том и
состоит, чтобы посмотреть, как S растёт с n:

| q | рёбер в сумме, от самой мелкой подвыборки до самой крупной |
|---|---|
| 0.0 | 50 → 255 |
| 0.5 | 25 → 128 |
| 0.9 | 5 → 25 |

При q = 0.9 весь фит опирается на 5–25 рёбер — отсюда рост шума на хвосте.

## Конфигурация оценки

Зафиксирована в [`scripts/config.py`](scripts/config.py). Выбрана перебором вариантов
([`scripts/variant_sweep.py`](scripts/variant_sweep.py)), каждый пункт обоснован измерением.
Относительный шум одного измерения **0.026 против 0.114 у настроек статьи**.

| параметр | значение | почему |
|---|---|---|
| подвыборка | **без возвращения** | бутстрап оставляет ~37% дубликатов при n = L и завышает d на 12–18% |
| пул | **2L токенов** | подвыборки из широкого пула вдвое снижают шум, не меняя d |
| повторов | **32** | шум 0.114 → 0.076; на 64 всего 0.066 за двойную цену |
| сетка n | **8 точек лог-шкалы на [0.2L, L]** | форма сетки не влияет вообще; диапазон влияет сильно |
| обрезка | **дробная** | целочисленная даёт пилу на сетке q мельче 0.1 |
| L | **абсолютный, 256** | доля от длины текста возвращает зависимость от длины |
| L от q | **не зависит** | масштабирование ломает интерпретацию кривой |

Настройки статьи сохранены под флагом `--legacy` — воспроизводимость не потеряна.

## Что выяснили

### 1. Пила на кривых — артефакт округления

Обрезка `k = floor(q·m)`, где `m = n−1` меняется по сетке фита. Эффективная обрезанная
доля `k/m` получается разной для разных n: на самой мелкой подвыборке `floor` округляет q
вниз на величину до `0.5/m`, там обрезается меньше, S завышена, наклон кренится, d занижена.

Проявляется как пила с провалами на q = 0.05, 0.15, 0.25, 0.35, 0.45. На исходной сетке
статьи (шаг 0.1) невидима — она попадает только в точки, где `floor` точен при всех m.
Воспроизвели на равномерном облаке в 8D, где истинная кривая обязана быть гладкой:
амплитуда 0.5–0.9 в d.

**Починка:** граничному ребру даётся дробный вес `1 − frac(q·m)`, обрезанная доля равна
ровно q при любом n. `discrete=True` возвращает поведение статьи.

### 2. Форма кривых по жанрам

[`figures/human_L256_v2_curves.png`](figures/human_L256_v2_curves.png) — 100 текстов на жанр, L = 256.

- **q_small** — сигмоида с насыщением. Порядок жанров устойчив: xsum > amazon_reviews >
  writingprompts > academic_abstracts. На плато жанры расходятся сильнее, чем в начале:
  `writingprompts` выходит на ~14 и загибается вниз, остальные идут к 16–17.
- **q_large** — монотонное падение до плато ~3–3.6 при q ≈ 0.7. Кривые **сходятся**:
  мелкомасштабная геометрия у всех жанров почти одинаковая.
- **q0.5_range** — гладкий монотонный рост, порядок жанров сохраняется везде.

Вывод: вся жанровая информация сидит на **крупном** масштабе.

### 3. Что отличает тексты с высокой и низкой размерностью

[`scripts/inspect_extremes.py`](scripts/inspect_extremes.py), результат в `results/extremes_*.txt`.

**Низкая d** — диалоги и верлибр с жёсткой повторяющейся разметкой (спикер-теги,
переводы строк, анафора). **Высокая d** — плотная экспозиционная проза с потоком
уникальных сущностей, чисел и терминов.

Корреляции: `upper_frac` −0.51, `n_sents` −0.43, `punct_frac` −0.42, а лексические метрики
почти нулевые (ttr 0.03, hapax 0.03). То есть на крупном масштабе играет **структурная
повторяемость**, а не словарное разнообразие.

### 4. Качество оценки: два независимых критерия

[`scripts/variance_decomp.py`](scripts/variance_decomp.py) — разложение дисперсии на
шум оценки и реальные различия между текстами (одни и те же тексты под разными сидами).

- `cv_within` = относительный шум одного измерения
- `resid_rmse` = отклонение от степенного закона в лог-пространстве
- `d_se` = неопределённость d, перенесённая с наклона дельта-методом

**Хороший фит ≠ надёжная d.** Поскольку `d = α/(1−b)`, ошибка наклона усиливается **в d раз**.
При больших d (q_small на хвосте) степенной закон выполняется идеально (невязка 0.3%),
но усиление ×21 превращает погрешность наклона 0.005 в 11% ошибки в d. А при `q_large ≥ 0.8`
ломается уже сама модель (невязка 4.3%). Оба хвоста шумные, но по противоположным причинам.

### 5. L влияет на d очень сильно, и это не лечится

[`scripts/length_sweep.py`](scripts/length_sweep.py), [`figures/length_dependence.png`](figures/length_dependence.png).

`d ~ L^b`, где b ≈ −0.21 при q = 0 и до −0.43 при q_small = 0.3. Улучшенная конфигурация
почти не помогла (было −0.24 и −0.49) — это **структурное свойство**, а не артефакт.
В доступном диапазоне не сходится: каждое удвоение L снимает 8–10%.

Трактовка: d меряется по окну n ∈ [0.2L, L], при разных L это разные диапазоны масштабов.
Вся идея qPHD в том, что размерность зависит от масштаба — странно ожидать независимости
от окна, в котором её меряют.

**Практический вывод: L надо выравнивать строго. Абсолютные значения d без указания L
смысла не имеют.**

Есть одна почти L-инвариантная точка — **q_large ≈ 0.6** (показатель −0.13,
d(768)/d(256) = 1.01). Единственный режим, который можно сравнивать между текстами
разной длины без строгого выравнивания.

### 6. Длина текста при фиксированном L не важна; доля от длины — плохая идея

[`scripts/exp_length_policy.py`](scripts/exp_length_policy.py), [`figures/length_policy.png`](figures/length_policy.png).

Регрессия log d на log(числа токенов) **внутри жанра**, 160 текстов длиной 322–881:

| политика | q=0 | 0.3 | 0.6 | 0.9 |
|---|---|---|---|---|
| L = 256 абсолютный | −0.014 | +0.011 | −0.067 | −0.051 |
| L = 256, пул 2L | +0.012 | +0.031 | −0.038 | −0.010 |
| L = весь текст | −0.134 | −0.354 | −0.277 | −0.149 |
| L = половина текста | −0.268 | −0.558 | −0.381 | −0.319 |

Абсолютный L даёт наклон, неотличимый от нуля. Долевой **импортирует** зависимость от L
прямо в результат: раз `d ~ L^−0.2`, а L пропорционален длине, то и d становится функцией длины.

### 7. Масштабировать L по q не нужно

[`scripts/exp_L_per_q.py`](scripts/exp_L_per_q.py), [`figures/L_per_q.png`](figures/L_per_q.png).

Идея была: при большом q рёбер остаётся мало, увеличим L как `N/(1−q)`, чтобы
число оставшихся рёбер не зависело от q. Работает — шум перестаёт расти с q и даже падает
(0.070 → 0.037). Но:

1. **Проблема уже решена другим способом.** При фиксированном L = 228 в новой конфигурации
   шум не превышает 0.068 на всём диапазоне (против 0.228 в старой).
2. **Ось q перестаёт быть осью q.** Кривая становится немонотонной. Проверили: если
   вернуть масштабируемое плечо к общему L поправкой `L^0.21`, оно совпадает с фиксированным
   (16.03 против 16.10 при q = 0.6; 16.66 против 16.84 при q = 0.8). Вся разница —
   известная зависимость от L, а не новая информация.
3. **Дорого по данным.** Требует текстов длиннее 500 токенов, что отсекает почти весь
   academic_abstracts (8 текстов из 500).

```
scripts/
  config.py               зафиксированная конфигурация оценки + обоснование

  run_human_baseline.py   основной прогон по жанрам   → results/human_L{L}_v2.csv

  variance_decomp.py      шум оценки vs различия между текстами

  summarize_variants.py   сводка по перебору
  length_sweep.py         зависимость d от L
  exp_length_policy.py    эксперимент 1: абсолютный L vs доля
  exp_L_per_q.py          эксперимент 2: L(q)
  inspect_extremes.py     тексты на краях распределения d

figures/                  графики
results/                  таблицы и логи прогонов
cache/embeds/             кэш эмбеддингов (в гит не идёт)
```
